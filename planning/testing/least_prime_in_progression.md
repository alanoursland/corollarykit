# Testing: `least_prime_in_progression(a, q)`

Plan: [../least_prime_in_progression.md](../least_prime_in_progression.md)

## 1. Reference values

- **A brute-force table, generated by us:** the least prime in every class (a, q) with gcd(a, q) = 1, for q ≤ 2000. That's about 1.2 million entries, stored compressed with its generator script.
- Cross-check against OEIS A034694 (smallest prime ≡ 1 mod n). The OEIS ids cited in the plan file are to be confirmed and corrected.
- The worst case for each q, max over a, taken from the same table. This is what tests the ceiling.

## 2. Oracle comparison

- For random q up to 2⁴⁰ and random a, compare with a naive scan using PARI `isprime` (`oracle_pari`).
- **NTT primes:** `ntt_prime(bits, k)` against published NTT moduli, such as 998244353 = 119·2²³ + 1, 3329 (Kyber) and 8 380 417 (Dilithium).

## 3. Properties

- The result is prime, ≡ a (mod q), and no smaller candidate in the class is prime. Checked in full by sieving for p < 10⁹.
- The result is independent of block size: run with block sizes of 1, 7 and 2¹⁶.

## 4. Edge cases

- **Small q:** q = 1 → 2; (1, 2) → 3.
- **Answers that are sieving primes:** (2, 3) → 2; (3, 4) → 3; (5, 6) → 5. Also every (r mod q, q) with r a small prime and q ≤ 100.
- gcd(a, q) > 1 raises `ValueError`. a ≥ q and a < 0 are reduced first. q ≤ 0 is rejected.
- `prime_with_residue(a, q, min=…)` and `ntt_prime` **have no ceiling from the least-prime theorem.** Test that they honor the explicit `budget=` argument and return the defined no-result value when it runs out, without raising `InconsistencyError`.

## 5. Bases and policy

- The ceiling applies only within each basis's recorded domain of q. Test the domain edges once they are recorded, including `lls2015` at q = 3 versus 4.
- Under "proof", candidates are accepted only with a proof. A stub BPSW that wrongly accepts a composite is used to check this, as in `next_prime`.

## 6. Certificates

- `membership`: the verifier checks p ≡ a (mod q) and p's primality certificate.
- `full`: the verifier checks a factor or witness for every earlier candidate.
- **Corruption tests:**
  - remove one candidate's entry (a hole), which must fail;
  - give a factor that doesn't divide its candidate, which must fail;
  - start the list at the wrong first candidate, which must fail.

## 7. Failure paths

- A fake ceiling of 10 on (1, 7), whose answer is 29, must raise `InconsistencyError`.

## 8. Performance

- Worst-case q from the table, up to 2000, and random q up to 2⁶⁴: candidates scanned, sieve time and test time.
