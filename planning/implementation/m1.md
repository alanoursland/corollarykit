# M1 implementation sketch: LP certificate checker

M1 delivers `check_lp_certificate` for standard-form LPs, per [../specs/lp_certificate_checker.md](../specs/lp_certificate_checker.md), and the second, independent checker that tests it. The exit criteria are in [../milestones.md](../milestones.md#m1-lp-certificate-checker). The test requirements are in [../testing/lp_certificate_checker.md](../testing/lp_certificate_checker.md).

The checker is **trusted code**: a `valid=True` verdict is meant to be a complete proof. Two rules follow from that:
1. `certificate.py` stays small (about 200 lines), uses only the standard library, and has no clever tricks.
2. Everything that is clever (exact solvers, generators, oracles) lives in the tests, where a bug can only cause a false test failure, never a false proof.

Conventions are as in [m0.md](m0.md): "must" marks a contract the tests enforce, and pseudocode is Python-flavored.

## Spec amendments (made in PR 1)

Writing the sketch exposed six gaps in the spec. PR 1 fixes the spec text first, so the code and the spec agree:

| # | Spec says | Change | Why |
|---|---|---|---|
| 1 | "A float raises `TypeError`" | Applies to the **problem** only. A float, or any non-rational, inside a **certificate** produces a `type` failure. `coerce_float=True` (an argument of `check_lp_certificate`) converts finite floats exactly in both. | A certificate is untrusted input, and the spec also says a malformed certificate never raises. |
| 2 | `Failure(check, index, lhs, rhs)`, with the relation given as "lhs <op> rhs" | Add `op: str` (`"=="`, `"<="`, `">="`, `"<"`, `">"`) and `field: str \| None` (`"x"`, `"y"`, `"d"`, `"value"`). `lhs` and `rhs` become `Fraction \| None`, since they are None for `shape`, `type` and `claim` failures. | A failure message can't be read unambiguously without the relation. The two checkers' failure sets are compared on (check, field, index). |
| 3 | Check names | Add `type` (an entry isn't a rational) and `claim` (the certificate object isn't one of the three classes). | Needed for the "never raises" rule. |
| 4 | `max_failures` | Must be an int ≥ 1, or None for no limit. Anything else raises `ValueError`. Validity is decided correctly even when the list is capped. | The testing plan asks that `max_failures=0` behave "as specified", so it needs a specification. |
| 5 | Checks run "until `max_failures`" | Three stages: **shape**, then **type**, then **numeric**. A failure in one stage skips the later stages. Within the numeric stage the check order is fixed (see below). | Gives deterministic failure sets that the independent checker can reproduce exactly. |
| 6 | Output type | `CheckResult` is **not** a `corollarykit.results.Result`. It is a verdict on someone else's claim, with no basis and no claims of its own. | Keeps the trusted module free of the registry. A test checks it never consults the registry. |
| 7 | Matrix construction | `SparseMatrix` enforces its invariants on **every** construction path, including direct `SparseMatrix(...)`: `rows` has exactly m entries, column indices are in range and strictly ascending, and values are nonzero base `Fraction`s. `StandardFormLP` accepts only an exact `SparseMatrix`, not a subclass. | Otherwise `SparseMatrix(m=1, n=1, rows=())` with b = (1,) gives `_A_times` nothing to compare, and a bogus `Optimal` passes. (Astra review.) |
| 8 | Certificate inputs | Containers must be **exactly** `list` or `tuple`, not subclasses, and are copied before use. Every accepted scalar is normalized to a **base** `Fraction` before any arithmetic: int and Fraction subclasses, `numbers.Rational` types and (with `coerce_float`) float subclasses are converted, and anything that fails conversion is a `type` failure. | A subclass can make `len` or iteration raise or disagree, or bring custom arithmetic into the proof checks. (Astra review.) |
| 9 | Empty dense matrix | `StandardFormLP.build` passes `n = len(c)` to `from_dense`, and `from_dense` requires `n` when there are no rows. | `build([], [], [1])` must mean one variable and no constraints, not a dimension error. (Astra review.) |

## PR 1: Types (`src/corollarykit/lp/certificate.py`, first half)

### Scalars

```
def _exact_int(v) -> int | None:
    """An exact built-in int equal to v, or None. Never raises."""
    try:
        n = int(v)                       # an int subclass's __int__ could misbehave
    except Exception:
        return None
    return n if type(n) is int else None

def _rational(v, *, coerce_float) -> Fraction | None:
    """A base Fraction for an accepted scalar, else None. Never raises.
    Exact-type checks come first; anything else is converted, never passed through."""
    t = type(v)
    if t is bool:                        return None          # bool is an int subclass: reject
    if t is int:                         return Fraction(v)
    if t is Fraction:                    return v             # base Fraction: its parts are ints
    if isinstance(v, bool):              return None          # (unreachable, but explicit)
    if isinstance(v, numbers.Rational):  # int/Fraction subclasses, gmpy2.mpq, other rationals
        try:
            num, den = _exact_int(v.numerator), _exact_int(v.denominator)
        except Exception:
            return None
        if num is None or den is None or den == 0: return None
        return Fraction(num, den)        # a fresh base Fraction: no foreign arithmetic survives
    if isinstance(v, float) and coerce_float:
        try:
            f = float(v)                 # float subclass (e.g. numpy.float64) -> base float
        except Exception:
            return None
        if type(f) is not float or not math.isfinite(f): return None
        return Fraction(f)               # exact binary value
    return None                          # float without coerce, Decimal, str, None, ...
```

The `except Exception` clauses are the only ones in the module, and they are deliberate: they turn a misbehaving third-party object into a `type` failure. They wrap only calls into foreign objects (`int()`, `.numerator`, `float()`), never our own arithmetic, so they can't hide a bug in the checker.

Prototyped while revising the sketch:
- an int subclass and a `Fraction` subclass whose `__mul__`, `__add__` and `__eq__` raise both come out as base `Fraction`s with the same value, and base arithmetic on them works;
- a `numbers.Rational` whose `numerator` raises, and a float subclass whose `__float__` raises, both give None;
- `numpy.int64(4)` is accepted as 4, since NumPy registers it as `numbers.Integral`, which is correct for an exact integer;
- `numpy.float64(0.25)` with `coerce_float` gives 1/4;
- NaN and ±inf are rejected.

For the **problem**, a wrapper raises `TypeError(f"{where}: {type(v).__name__} is not an exact rational")` when `_rational` returns None.

### `SparseMatrix`

```
@dataclass(frozen=True)
class SparseMatrix:
    m: int
    n: int
    rows: tuple[tuple[tuple[int, Fraction], ...], ...]   # rows[i] = ((j, a_ij), ...), j ascending, a_ij != 0

    @classmethod
    def from_coo(cls, m, n, rows, cols, vals, *, coerce_float=False):
        require m, n are ints >= 0 (not bool)                         else ValueError
        require len(rows) == len(cols) == len(vals)                   else ValueError
        acc = {}                                                      # (i, j) -> Fraction
        for i, j, v in zip(rows, cols, vals):
            require 0 <= i < m and 0 <= j < n (ints, not bool)        else ValueError
            acc[(i, j)] = acc.get((i, j), 0) + _problem_scalar(v)     # duplicates are summed
        per_row = [[] for _ in range(m)]
        for (i, j), v in sorted(acc.items()):
            if v != 0: per_row[i].append((j, v))                      # explicit zeros dropped after summing
        return cls(m, n, tuple(tuple(r) for r in per_row))

    @classmethod
    def from_dense(cls, rows_of_values, *, n=None, coerce_float=False):
        m = len(rows_of_values)
        if m == 0:
            require n is not None                                     else ValueError   # no rows: width unknown
        else:
            width = len(rows_of_values[0])
            require n is None or n == width                           else ValueError
            n = width
        require every row has length n                               else ValueError
        return from_coo over all nonzero positions

    @property
    def nnz(self): return sum(len(r) for r in self.rows)
```

Canonical storage (sorted, zeros dropped, duplicates summed) means two equal matrices compare equal. Canonicalization happens only here, in the problem constructor, never in the checking path.

**Invariants, enforced on every construction path** (`__post_init__`, so a direct `SparseMatrix(...)` call is checked too):

```
def __post_init__(self):
    require type(m) is int and type(n) is int and m >= 0 and n >= 0            else ValueError
    require type(self.rows) is tuple and len(self.rows) == m                    else ValueError
    for i, row in enumerate(self.rows):
        require type(row) is tuple                                              else ValueError
        prev = -1
        for entry in row:
            require type(entry) is tuple and len(entry) == 2                    else ValueError
            j, v = entry
            require type(j) is int and prev < j < n                             else ValueError  # in range, strictly ascending
            require type(v) is Fraction and v != 0                              else ValueError  # base Fraction, nonzero
            prev = j
```

`SparseMatrix(m=1, n=1, rows=())` now raises, because `rows` has 0 entries instead of 1. `StandardFormLP.__post_init__` requires `type(A) is SparseMatrix`, `type(b) is tuple` with base `Fraction` entries of length m, and the same for `c` with length n.

### `StandardFormLP`

```
@dataclass(frozen=True)
class StandardFormLP:            # minimize c^T x subject to A x = b, x >= 0
    A: SparseMatrix
    b: tuple[Fraction, ...]
    c: tuple[Fraction, ...]

    @classmethod
    def build(cls, A, b, c, *, coerce_float=False):
        A = A if type(A) is SparseMatrix else SparseMatrix.from_dense(A, n=len(c), coerce_float=...)
        require len(b) == A.m and len(c) == A.n                        else ValueError
        return cls(A, tuple(_problem_scalar(v) for v in b), tuple(_problem_scalar(v) for v in c))

    @property
    def m(self): return self.A.m
    @property
    def n(self): return self.A.n
```

`__post_init__` re-validates when the dataclass is constructed directly, so `StandardFormLP(A, b, c)` with bad lengths or non-Fraction entries also raises.

### Certificates

```
@dataclass(frozen=True)
class Optimal:     x: Any; y: Any; value: Any = None
@dataclass(frozen=True)
class Infeasible:  y: Any
@dataclass(frozen=True)
class Unbounded:   x: Any; d: Any
```

These classes do **no validation at construction**, so building a certificate can't raise however wrong it is. Every problem is reported by the checker.

### Output

```
@dataclass(frozen=True)
class Failure:
    check: str            # shape | type | claim | primal_eq | primal_nonneg | dual_feas | duality_gap
                          # | value | farkas_dual | farkas_obj | ray_eq | ray_nonneg | ray_obj
    field: str | None     # "x" | "y" | "d" | "value" | None
    index: int | None     # row i or column j, when the check is per-row or per-column
    lhs: Fraction | None
    op: str | None        # "==" | "<=" | ">=" | "<" | ">"
    rhs: Fraction | None
    detail: str = ""      # human text, e.g. "expected length 3, got 2"

    def __str__(self): e.g. "dual_feas[j=2]: (A^T y)_j = 5/2 <= c_j = 2 is false"

@dataclass(frozen=True)
class CheckResult:
    valid: bool
    claim: str                       # "optimal" | "infeasible" | "unbounded" | "unknown"
    failures: tuple[Failure, ...]    # empty iff valid
    objective: Fraction | None       # c^T x for optimal/unbounded once shape and type pass
    truncated: bool = False          # True when more failures existed than max_failures
```

## PR 2: The checker (`certificate.py`, second half)

### Exact linear algebra helpers

```
def _dot(pairs) -> Fraction:
    """sum of a*b over (a, b) pairs, with a single normalization at the end."""
    prods = [a * b for a, b in pairs]               # each product is a reduced Fraction
    if not prods: return Fraction(0)
    L = math.lcm(*(p.denominator for p in prods))
    return Fraction(sum(p.numerator * (L // p.denominator) for p in prods), L)

def _A_times(A, v)  -> list[Fraction]: return [_dot((a, v[j]) for j, a in row) for row in A.rows]

def _At_times(A, w) -> list[Fraction]:              # (A^T w)_j, one pass over the rows
    cols = [[] for _ in range(A.n)]
    for i, row in enumerate(A.rows):
        if w[i] != 0:
            for j, a in row: cols[j].append((a, w[i]))
    return [_dot(c) for c in cols]
```

`_dot` puts all the terms of a row over their lcm and reduces once, instead of normalizing after every addition. This is the bit-cost optimization the spec asks for. It stays simple enough to audit.

### Driver

```
CLAIMS = {Optimal: "optimal", Infeasible: "infeasible", Unbounded: "unbounded"}
FIELDS = {Optimal: [("x", "n"), ("y", "m")], Infeasible: [("y", "m")], Unbounded: [("x", "n"), ("d", "n")]}

def check_lp_certificate(problem, cert, *, max_failures=10, coerce_float=False) -> CheckResult:
    require isinstance(problem, StandardFormLP)                        else TypeError   (caller error)
    require max_failures is None or (int, not bool, >= 1)              else ValueError
    out = _Collector(max_failures)

    kind = type(cert)                                                  # exact class, not isinstance:
    if kind not in CLAIMS:                                             # a subclass could override fields
        out.add(Failure("claim", None, None, None, None, None, f"not a certificate: {kind.__name__}"))
        return out.result("unknown", objective=None)
    claim = CLAIMS[kind]

    # Stage 1: shape. Vectors must be list or tuple of the right length.
    vecs = {}
    for name, dim in FIELDS[kind]:
        v = getattr(cert, name); want = problem.m if dim == "m" else problem.n
        if type(v) not in (list, tuple):                      out.add(shape(name, f"not a list/tuple: {type(v).__name__}"))
        else:
            snap = tuple(v)                                   # exact list/tuple: len and iteration are safe
            if len(snap) != want:                             out.add(shape(name, f"expected length {want}, got {len(snap)}"))
            else: vecs[name] = snap                           # later code sees only this snapshot
    if out.any(): return out.result(claim, objective=None)

    # Stage 2: type. Every entry, and Optimal.value when given, must be an exact rational.
    conv = {}
    for name, v in vecs.items():
        conv[name] = [_rational(e, coerce_float=coerce_float) for e in v]
        for idx, e in enumerate(conv[name]):
            if e is None: out.add(Failure("type", name, idx, None, None, None, type_name(v[idx])))
    value = None
    if kind is Optimal and cert.value is not None:
        value = _rational(cert.value, coerce_float=coerce_float)
        if value is None: out.add(Failure("type", "value", None, None, None, None, ...))
    if out.any(): return out.result(claim, objective=None)

    # Stage 3: numeric checks. The order is fixed and part of the contract.
    A, b, c = problem.A, problem.b, problem.c
    if kind is Optimal:
        x, y = conv["x"], conv["y"]
        _check_eq(out, "primal_eq", "x", _A_times(A, x), b)           # (Ax)_i == b_i
        _check_cmp(out, "primal_nonneg", "x", x, ">=", 0)             # x_j >= 0
        _check_cmp(out, "dual_feas", "y", _At_times(A, y), "<=", c)   # (A^T y)_j <= c_j
        cx, by = _dot(zip(c, x)), _dot(zip(b, y))
        if cx != by: out.add(Failure("duality_gap", None, None, cx, "==", by))
        if value is not None and value != cx: out.add(Failure("value", "value", None, value, "==", cx))
        objective = cx
    elif kind is Infeasible:
        y = conv["y"]
        _check_cmp(out, "farkas_dual", "y", _At_times(A, y), "<=", 0) # (A^T y)_j <= 0
        by = _dot(zip(b, y))
        if not by > 0: out.add(Failure("farkas_obj", "y", None, by, ">", 0))
        objective = None
    else:  # Unbounded
        x, d = conv["x"], conv["d"]
        _check_eq(out, "primal_eq", "x", _A_times(A, x), b)           # x is feasible ...
        _check_cmp(out, "primal_nonneg", "x", x, ">=", 0)
        _check_eq(out, "ray_eq", "d", _A_times(A, d), [0] * A.m)      # ... and d is an improving ray
        _check_cmp(out, "ray_nonneg", "d", d, ">=", 0)
        cd = _dot(zip(c, d))
        if not cd < 0: out.add(Failure("ray_obj", "d", None, cd, "<", 0))
        objective = _dot(zip(c, x))
    return out.result(claim, objective=objective)
```

`_check_eq` and `_check_cmp` loop over indices and add a `Failure(check, field, index, lhs, op, rhs)` for each index where the relation is false. The right-hand side can be a vector or a scalar applied to every index.

`_Collector.add` appends until the cap is reached and sets `truncated` after that. Because `add` is only called when a failure exists, a capped run still knows the certificate is invalid. Validity never depends on the cap.

### Why each check set is sufficient

These are the proofs the reviewer of `certificate.py` must agree with. Copy them into the module docstring.

- **Optimal:** for any feasible x′, cᵀx′ ≥ (Aᵀy)ᵀx′ = yᵀAx′ = bᵀy. The first step uses x′ ≥ 0 and c ≥ Aᵀy. So bᵀy is a lower bound, and a feasible x with cᵀx = bᵀy attains it. Hence x is optimal with value cᵀx.
- **Infeasible:** if Ax = b with x ≥ 0, then bᵀy = (Aᵀy)ᵀx ≤ 0, since Aᵀy ≤ 0 and x ≥ 0. That contradicts bᵀy > 0.
- **Unbounded:** x + t·d is feasible for all t ≥ 0, because A(x + td) = b and x + td ≥ 0. Its objective cᵀx + t·cᵀd → −∞, since cᵀd < 0.

### Complexity

- `_A_times`: O(nnz) multiplications plus one lcm and one reduction per row.
- `_At_times`: O(nnz).
- The rest: O(m + n).

So a check is **O(nnz + m + n) rational operations**. Bit cost grows with entry sizes; the huge-rational test bounds it in practice.

## PR 3: Independent checker (`tests/verify/lp.py`)

This one follows the independence rule: no `corollarykit` import except the registry, which it doesn't need. It takes **plain data** and is written as differently as reasonable from the library:
- dense matrices;
- plain `fractions.Fraction` sums, with no lcm trick;
- index loops written out;
- no early exit within a stage.

```
def check(plain: dict) -> list[tuple[str, str | None, int | None]]:
    """plain = {"A": dense list of lists, "b": [...], "c": [...], "claim": "optimal"|...,
                "x": ..., "y": ..., "d": ..., "value": ..., "coerce_float": bool}
    Returns the set of failures as (check, field, index), sorted. An empty list means valid."""
```

It implements the same three-stage semantics from the spec amendments above. They are written down in that table, so this checker is built from the spec, not from the library code.

**Conversion for comparison** (in the test file, not in `verify/`): the verifier must not see the problem through the library's normalization, or both checkers could agree on the same wrongly normalized matrix. So:
- The generators keep the **raw input**: the COO triples (rows, cols, vals), with duplicates and explicit zeros, or the raw dense rows.
- The test assembles the dense matrix itself from that raw input. It sums duplicates in a plain double loop that shares no code with `SparseMatrix`, and passes that to the verifier.
- The certificate fields are copied **without converting them**. Floats, strings, subclasses and objects stay as they are, so both checkers see identical raw certificates.
- A separate test asserts that `SparseMatrix.from_coo(raw)`, densified, equals the independently assembled matrix. That test checks the canonicalization directly.

**Agreement contract:** for every generated (problem, certificate) pair, with `max_failures=None`:

```
sorted((f.check, f.field, f.index) for f in lib.failures) == verify.lp.check(plain)
```

That covers more than validity: it compares the complete failure set. A disagreement in a single index fails the test.

## PR 4: Oracles and property tests

### `tests/_lp_oracle.py`

These are test helpers, not trusted code. They are cross-checked against each other.

**(a) Status by enumeration**, for small sizes (m ≤ 4, n ≤ 6). It answers "what is true about this LP?" with no duality and no pivoting:

```
def solve_subset(A, b, S) -> tuple | None:
    """The unique x_S with A[:, S] x_S = b when the columns are independent and the system is
    consistent, else None. Exact Gaussian elimination in Fractions."""

def bfs_list(A, b):            # all basic feasible solutions
    out = []
    for S in all subsets of columns with |S| <= m (including the empty set, for b = 0):
        xs = solve_subset(A, b, S)
        if xs is not None and all(v >= 0 for v in xs): out.append(scatter(xs, S, n))
    return dedupe(out)

def exact_status(A, b, c):
    verts = bfs_list(A, b)
    if not verts: return ("infeasible",)              # a nonempty {Ax=b, x>=0} has a vertex
    # An improving ray exists iff the polytope {Ad=0, d>=0, sum d = 1} has a vertex with c^T d < 0.
    rays = bfs_list(A + [[1]*n], [0]*m + [1])
    if any(dot(c, d) < 0 for d in rays): return ("unbounded",)
    return ("optimal", min(dot(c, v) for v in verts))
```

Correctness argument, for reviewers:
- {x : Ax = b, x ≥ 0} contains no line, so if it is nonempty it has a vertex.
- A linear objective that is bounded below is minimized at a vertex.
- The LP is unbounded iff it is feasible and some d ≥ 0 with Ad = 0 has cᵀd < 0. Scaling d so its entries sum to 1 puts it in a bounded polytope with no lines, and the minimum of cᵀd over that polytope is attained at a vertex.

**(b) Certificates by exact simplex** (Bland's rule, so it cannot cycle). This produces certificates for the completeness tests:

```
def simplex_certificate(A, b, c) -> Optimal | Infeasible | Unbounded:
    # 0. Remove dependent rows by row reduction of [A | b], recording multipliers.
    #    A dependent row with an inconsistent right-hand side gives a Farkas y with
    #    A^T y = 0 and b^T y != 0; scale it so b^T y > 0, and return Infeasible(y).
    # 1. Flip the sign of rows with b_i < 0, remembering the flips.
    # 2. Phase I: min 1^T a  s.t.  A x + a = b, x, a >= 0, starting from basis = artificials.
    #    Pivot with Bland's rule until the reduced costs are >= 0.
    #    If the optimum is > 0, the Phase I dual y satisfies A^T y <= 0 and b^T y > 0.
    #    Undo the sign flips, map y back to the original rows (dropped rows get 0), return Infeasible(y).
    # 3. Drive degenerate artificials out of the basis (possible because rows are independent now).
    # 4. Phase II on the original c with Bland's rule:
    #    - entering column j with no positive entry in B^-1 A_j  ->  ray d (d_j = 1, d_B = -B^-1 A_j),
    #      return Unbounded(x = current BFS, d);
    #    - all reduced costs >= 0  ->  y = B^-T c_B (undo flips, map back), return Optimal(x, y, c^T x).
```

**Prototyped while writing this sketch:** both oracles and the numeric checks were run in a scratch script on 4000 random LPs (m ≤ 4, n ≤ 6, entries in [−5, 5], 40 % zeros, including rank-deficient A). They covered 1826 infeasible, 1187 optimal and 987 unbounded cases. In every case the oracles agreed on status and value, and every simplex certificate passed the checks. Two details the prototype settled:
- The Phase I dual u = B⁻ᵀc_B for cost 1ᵀa is itself the Farkas vector: Aᵀu ≤ 0 and bᵀu > 0. No sign change is needed.
- Rows dropped as dependent get yᵢ = 0. Rows whose sign was flipped get yᵢ negated back.

**Cross-check of the oracles:** for every generated LP, the claim of `simplex_certificate` must equal `exact_status`, and the optimal values must agree. This is run before any checker test uses either oracle. If it fails, the oracles are wrong and the checker tests don't run.

### Hypothesis strategies (`tests/_lp_strategies.py`)

- `lps()`: m ∈ [0, 4], n ∈ [0, 6], integer entries in [−5, 5] with about 40 % zeros. Constructed both ways: via COO, with duplicates and explicit zeros mixed in, and via dense.
- `valid_certs(lp)`: from `simplex_certificate`.
- `perturbed(cert)`: one coordinate ± 1/7, or a sign flip, or the value field off by one.
- `garbage_certs(lp)`: an arbitrary class among the three, or a random non-certificate object. Fields are drawn from lists or tuples of the wrong or right length, and **from hostile containers**: a list subclass whose `__len__` or `__iter__` raises, or whose `__len__` disagrees with its iteration. Entries are drawn from:
  - ints, Fractions, floats (including NaN and ±inf), None, strings, bools, nested lists;
  - a `numbers.Rational` subclass whose `numerator` raises;
  - an int subclass and a `Fraction` subclass that override `__mul__`, `__add__` and `__eq__` to lie;
  - a float subclass that overrides `__float__`.

  The subclass scalars must either be normalized to base `Fraction`s, so the checker's verdict is the same as for the honest values, or rejected as `type` failures. Their overridden arithmetic must never run inside a check. One test asserts this by making the overridden methods raise.

### Property tests (`tests/test_lp_certificate_props.py`)

| Test | Assertion |
|---|---|
| **completeness** | `check(lp, simplex_certificate(lp)).valid`, for every generated LP |
| **soundness** | for any certificate (valid, perturbed or garbage): if `valid`, the claimed status equals `exact_status(lp)`, and for Optimal, the objective equals the true optimum |
| **perturbation** | a perturbed certificate is invalid, unless the independent checker also finds it valid. A perturbation can land on another genuine certificate, such as an alternative dual optimum. |
| **agreement** | the library and `verify.lp.check` give identical failure sets on every certificate type above |
| **never raises** | `check_lp_certificate` returns a `CheckResult` for every garbage certificate. Any exception fails the test. |
| **cap** | with `max_failures=k`, `failures` is the first k of the uncapped list, `truncated` is set exactly when the uncapped list was longer, and `valid` is unchanged |

## PR 5: Edge cases and remaining testing-plan items (`tests/test_lp_certificate.py`)

- **Hand-built cases:** one valid certificate of each type. Then, for each type, change one entry so that exactly one check fails, and assert the failure list equals `[that (check, field, index)]`.
- **Ray without a feasible point:** min −x₂ subject to x₁ = −1, with A = [[1, 0]], b = [−1], c = [0, −1].
  - `Unbounded(x=(−1, 0), d=(0, 1))` → exactly `[("primal_nonneg", "x", 0)]`.
  - `Unbounded` with x of length 1 → a `shape` failure, and no numeric checks run.
  - `Infeasible(y=(−1,))` → valid.
- **Degenerate shapes:**
  - m = 0: any x ≥ 0 is feasible; Optimal needs c ≥ 0 and y = (). Built through the **public** constructor `StandardFormLP.build([], [], c)`, both bounded (c = [1] with `Optimal(x=(0,), y=())`) and unbounded (c = [−1] with `Unbounded(x=(0,), d=(1,))`).
  - Direct construction: `SparseMatrix(m=1, n=1, rows=())`, out-of-range or descending column indices, zero or non-`Fraction` values, and a `SparseMatrix` subclass passed to `StandardFormLP`. All must raise `ValueError` or `TypeError`.
  - n = 0: x = (); feasible iff b = 0.
  - an empty A; a zero row with b_i ≠ 0, which is infeasible by y = ±eᵢ; a zero column.
- **COO canonicalization:** duplicates are summed, explicit zeros dropped, and a matrix built through COO equals the same matrix built dense.
- **Degenerate optimum with several dual solutions:** build a primal-degenerate LP. Enumerate dual vertices with the oracle, and check that every dual optimum, paired with the primal optimum, is accepted.
- **Huge rationals:** an LP with m = n = 3 and entries with 10⁴-digit numerators and denominators, with a valid certificate built by the oracle. It must be valid and finish in under 1 s, as a plain assertion on measured time.
- **Types:**
  - a float in the problem raises `TypeError`, and with `coerce_float=True` it is converted exactly (`Fraction(0.1)` ≠ 1/10, which the test asserts);
  - a float in a certificate gives a `type` failure;
  - NaN and ±inf are always rejected;
  - a bool is rejected everywhere;
  - `gmpy2.mpq` is accepted (with `@pytest.mark.skipif` when gmpy2 isn't installed; gmpy2 is an optional extra, not an oracle).
- **Never consults the registry:** monkeypatch `corollarykit.registry.get_basis`, `list_bases` and `_load` to raise. Then run the hand-built cases.
- **SciPy/HiGHS comparison** (`oracle_highs`, now mapped to the `scipy` module, with `scipy` added to the `oracles` extra):
  - solve random LPs with `scipy.optimize.linprog(method="highs")`;
  - rationalize the float solution and duals with `Fraction(v).limit_denominator(10**6)`, then check the result;
  - assert **soundness only**: when valid, the status equals `exact_status`;
  - record, but don't assert, how often the rationalized certificate is valid. Floating-point solutions are often slightly infeasible, which is exactly why this checker exists.
  - **One deterministic case must pass**, so the comparison can't succeed vacuously with zero accepted certificates: min x₁ + x₂ subject to x₁ + 2x₂ = 4 and 3x₁ + x₂ = 7. The unique solution is x = (2, 1) with value 3, and the duals are y = (2/5, 1/5). HiGHS's x and equality marginals, rationalized, must give a **valid** `Optimal`. Checked with SciPy 1.18.1: `res.eqlin.marginals` is (0.4, 0.2), which equals y for a minimization, and `limit_denominator(10**6)` recovers x = (2, 1) and y = (2/5, 1/5) exactly.
- **Performance** (`@pytest.mark.bench`, run by hand): check time at nnz = 10³, 10⁴, 10⁵ and 10⁶, with small and with 64-bit rationals. Record the times; linear growth is expected.

## Implementation notes (M1 as built)

Where the code departs from the sketch above:

- **No exact-type fast path in `_rational`.** Every accepted value goes through the `numbers.Rational` branch and is rebuilt from `int(numerator)` and `int(denominator)`. The fast path returned the same values, so mutmut could never tell it apart: it produced equivalent mutants.
- **`_exact_int` has no `type(n) is int` guard.** `int()` always returns an exact int: when `__int__` returns an int subclass, Python warns and copies the value. The guard was dead code. A test covers this case and expects the value to be accepted, with the warning.
- **No `zip(..., strict=True)` in the checking path.** The shape stage has already fixed every length, so `strict=` was redundant and produced equivalent mutants. `_vdot` and index loops replace it.
- **`from_coo` checks only the row index.** A negative row index would otherwise wrap into the last row. Column indices and the dimensions are checked once, by `SparseMatrix.__post_init__`.
- **`certificate.py` is about 470 lines, not 200.** The checking path (scalar conversion, `_dot` and the driver) is about 200. The rest is the problem types, their validation, and docstrings.
- **Mutation testing: 753 mutants, all killed, with no `# pragma: no mutate`.** The first run left 131 survivors:
  - about 60 were untested exception messages and failure details, now asserted;
  - a handful were equivalent mutants, removed by the simplifications above;
  - the rest were real test gaps, now covered: Rationals with a zero denominator or an unconvertible numerator, a non-int `n` with m ≥ 0, a list used as a matrix entry, a negative COO row index, `coerce_float` through `build`, the default cap of 10, and tuple certificates.
- **mutmut 3.8.1 works with the src layout** once `also_copy` includes `src` (see `[tool.mutmut]`), so the 2.5.x fallback wasn't needed.
- **`oracle_highs` maps to the `scipy` module,** and `scipy` is in the `oracles` extra. gmpy2 stays an optional extra, and its test is skipped when gmpy2 isn't installed.
